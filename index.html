Architecture: 1,117,137 shared neural parameters plus 480 consequence-prediction weights (1,117,617 total). 160-dimensional byte embeddings, 1,536 hidden units, four independent diagonal-projection attention heads, 512 relative positions, 16-byte block recurrence with BPTT, learned 2/4/8-byte filters, RMS normalization, and configurable one to four shared refinement cycles. Attention uses a single query and linear context storage.
Learning: Byte cross-entropy and supervised operation, reference and tool losses have checked gradients. AdamW uses clipping, per-tensor update ages, finite-value preflight, and atomic checkpoints. Consolidation replays supported verified experiences and rejects measured controller, byte-validation or consequence-prediction regressions.
Compatibility: Native complete-brain files contain weights, Adam state, organisms, examples, traces, goals and memory. Existing v2/v3 and original JSON checkpoints transfer only compatible submatrices. Their originals are preserved; fresh modules and optimizer moments require new training. Migration is not prediction-equivalent. Preserve an export from the old app when moving between browser storage origins.
Runtime: Opens as one offline HTML with no external model or mandatory package. Startup reads metadata and a controlled checkpoint, with no corpus scan or training. Weights, gradients and Adam buffers use approximately 17.9 MB before checkpoints, worker copies, source files and browser overhead. The configurable data budget bounds retained data and caches; the browser process is not hard-capped. Performance was tested in Chromium on the available runtime, not on a Celeron N4500.
Scope limits: The constructor needs explicit types, literals and expected-output examples. It produces bounded pure-data programs, not arbitrary applications. Refinement depth is configurable rather than a learned adaptive budget. The tool head is a supervised suggestion head; actual execution uses the existing permission-checked Code tools and learned text protocol. Automatic verified browser-tool feedback training is partial. Abstractions cover local two-node patterns. The Spine retains explicit fields rather than learning semantic compression. Consequence predictions cover state summaries rather than exact values. Transfer and evolution remain limited to supported graphs and finite tests. All partial systems are labelled in the table above.
Capability status: No frontier-model equivalence, general coding score or conversation-coherence result has been established. Fresh weights still need language data. Controller training alone does not train the byte output head. Tests demonstrate actual computation, learning and persistence; they do not prove broad competence.
Legacy research-core notes
This section describes the experimental browser research architecture preserved from the earlier Lumina build. It is separate from the hosted GPT-OSS-120B model used for chat and code generation. Fine-tuning the hosted base model is available through Alt + Shift + 9 and requires a separately configured training worker that explicitly supports the base model and chosen method. These local components are not a substitute for that worker.

Natural-language selection is learned, not a prompt lookup. Supply the interface, literal constants and expected behaviour. Search uses fit cases; final cases are reserved for checking the selected program. Supports pure data programs, not arbitrary web applications.
Code construction requires Plus or Pro. Selecting a local plan involves no payment. Counts one weekly request; tests and training use no messages.

Train task → program selection
Byte datasets train language prediction in Training. This corpus trains operation selection, reference pointers, bonds, capsules and optional labelled tool selection with real gradients through the same encoder.
Every reference program must pass its declared tests. Use split "val" for excluded tasks and "transfer" for excluded task families. A transfer family cannot also occur in training.
Documented IR v1 & dataset format
A program has version 1, a topological list of nodes, and one output reference. Nodes have an ID (n0…), an operation ID, and typed argument references: {"input":"a"}, {"ref":"n0"}, or {"const":1}. Skill calls use "skill:ID". Up to 24 supplied nodes; generated programs use at most six. Input types: number, string, boolean, array, object, null, any. Optional tool is an exact supported tool ID. Constants for learned construction must be declared in schema.constants. The constructor learns operation and pointer distributions; it does not infer arbitrary literal values.
Supervised learning & consolidation
Consolidation replays verified experiences, known correct targets for failed training tasks, and actual execution traces. It compares excluded task loss and consequence prediction error, and rolls back on regression. Without excluded validation tasks it refuses to retain consolidation updates.
No controller training has run.

 
Goal Crystals
Goals are explicit requirements. Program construction reads the selected goal's schema, expected tests and compute constraints. A completed goal means its declared tests passed.
Context Spine & Continuity Cells
The Spine keeps bounded explicit fields, priorities and expiration times. Continuity uses the trained block-recurrent state with a stop-gradient boundary between tasks. These are distinct from the 512-byte neural input.
No persistent task fields.
Free retains no conversation state. Plus and Pro use bounded session state. New Code task clears that task's continuity and retained fields. Nothing here guarantees long-conversation comprehension.

 
Measured evaluation
No intelligence ratings. Capability results require excluded tasks, expected outputs and executed checks. Engineering checks test implementation integrity; they do not measure general intelligence.

CODE CAPABILITIES
Browser tool library
Implemented browser tools with explicit permission and sandbox boundaries.
Tool boundary: The available tools listed above are callable from Code’s Tools drawer. The JavaScript console executes code in a browser worker. The browser cannot run system commands, install packages, or read private accounts. File selection uses the browser picker. Public URL reads depend on CORS. AI requests go through the Lumina backend; browser tools remain limited to their documented permissions.
Model tool protocol
A trained model can emit a complete fenced tool block containing JSON with name and arguments. Only validated calls execute, after a generated turn boundary (\nUser:). Truncated or malformed requests do not execute. File imports, downloads and URL fetches remain explicit browser actions. The model must learn this format from training data; no tool-choice competence is assumed. Each continuation receives only the last 512 bytes, visible under Model input.
